# Помощни скриптове (backend)

Идеята на тези скриптове е еднократно зареждане на статичен контент в Supabase
(блог статии, опресняване на снимки). **Продуктовият каталог се администрира
изцяло през админ панела** (`/admin/products`), затова за него вече няма seed
скрипт — старият `import:products` беше премахнат заедно с hardcoded списъка
`frontend/data/db.ts`.

## Предпоставки

1. Приложени са всички SQL миграции от `backend/supabase/migrations/` (виж
   `backend/supabase/README.md`).
2. Файл `backend/.env.local` съдържа поне:
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY`

## Налични команди

| Скрипт | Команда | Действие |
|--------|---------|----------|
| Блог импорт | `npm run import:blog` | Качва статиите от `frontend/data/blog/index.ts` в Supabase (`upsert` по `slug`; `view_count` се запазва ако записът вече съществува). |
| Блог импорт (dry-run) | `npm run import:blog -- --dry-run` | Само брой статии, без писане в БД. |
| Снимки на каталог | `npm run catalog:images` | Синхронизира липсващи снимки. |
| Снимки (само старите) | `npm run catalog:images:stale` | Обновява само остарелите. |
| Каталог Tempex | `npm run import:tempex` | Синхронизира всички стенни, подови, колонни и мултисплит климатици, включително отделните вътрешни и външни тела. |
| Tempex без запис | `npm run import:tempex -- --dry-run --output=tempex-preview.json` | Проверява всички страници и запазва извлечените данни за преглед, без достъп до базата. |
| Тестове Tempex | `npm run verify:tempex` | Проверява извличането с реални продуктови данни и избор на цена без монтаж. |

## Tempex

В админ панела: **Настройки → Каталози → Обнови каталог от Темпекс**.
Tempex е включен и в общата синхронизация на доставчиците. Не е нужна нова SQL миграция;
отчетът се съхранява в съществуващата таблица `settings` с ключ `tempex_catalog_sync`.
Едновременно може да работи само една Tempex синхронизация, включително между различни сървърни процеси.

Цените се извличат **само в EUR, с ДДС и без монтаж**. Когато стандартният вариант на
страницата е с монтаж, импортът изрично избира „Без монтаж“. `price_with_mount` не се
импортира; при нови записи остава `null`. Вътрешните и външните мултисплит тела са
отделни продукти в категория `multi`, с изрична бележка за обхвата на цената.

Извличат се всички големи снимки от продуктовата галерия, техническите характеристики,
описанието, функциите и връзки към приложените документи. Характеристиките, за които
няма отделно поле в каталога, се запазват в техническа таблица в описанието. Непосочени
стойности остават празни. Продукти без положителна публикувана цена или с цена по
запитване се пропускат, включително когато в публичния HTML има скрита числова сума.
Модели, предлагани единствено във вариант с монтаж, също се пропускат.

Съпоставяне към реалните полета на каталога:

| Полета | Източник и мерна единица |
| --- | --- |
| `name`, `model_code`, `brand_id`, `type_id`, `category_id`, `supplier_id`, `source_url` | Име, модел на конкретното тяло, производител, вид и изходна категория. „Серия“ и „Референция“ не се използват вместо модел. |
| `price` | Публикувана положителна цена в EUR с ДДС за вариант без монтаж. |
| `cooling_power_kw`, `heating_power_kw` | Номинална мощност; при `min / nom / max` се взема средната стойност. Общо означение „Капацитет kW“ не се представя като отделно потвърдено охлаждане или отопление. |
| `btu` | Номинален клас в хиляди BTU; при липса се определя по посочената номинална мощност. Пет доказани несъответствия на източника се обработват с тесни проверки в `verifiedTempexCorrections.ts` и връзки към производителите. |
| `noise_db` | Най-ниско посочено звуково налягане на вътрешното тяло; за отделно външно тяло — неговото налягане. Не се използва звуковата мощност. |
| `seer`, `scop`, `energy_class_cool`, `energy_class_heat`, `refrigerant` | Изричните технически характеристики на конкретния продукт. |
| `warranty_months` | Гаранция в месеци; годините се умножават по 12. |
| `weight_indoor_kg`, `weight_outdoor_kg` | Посочените тегла в kg на съответното тяло. |
| `dim_*_length_mm`, `dim_*_width_mm`, `dim_*_height_mm` | Ширина, дълбочина и височина от изходното `Ш × В × Д`, преобразувани към реда `Д × Ш × В` на каталога. Допълнителни размери на задната планка не заменят габаритната ширина. |
| `wifi`, `product_features` | Изрични характеристики и икони на текущия продукт; опционален Wi-Fi не се отбелязва като включен модул. |
| `product_images` | Цялата продуктова галерия в голям размер; избраната от Tempex корица е главна, независимо от мястото ѝ в масива. |
| `description`, `meta_title`, `meta_description` | Описание, пълна техническа таблица, функции, документи и обхват на цената (комплект / вътрешно / външно тяло). |
| `coverage_m2` | Само изрично посочена площ; без изчисляване по BTU или рекламни предположения. |

Не се заместват реални данни за покупки, продажби, серийни номера, складови бройки,
клиентски оценки или ръчно избрана публична видимост с информация от доставчика.

Новите продукти са „по поръчка“ и скрити за преглед, както при останалите доставчици.
Обновяването запазва складови количества, серийни номера, продажби, публична видимост и
настройки на магазина. Продукти от друг доставчик не се презаписват.
След пълна синхронизация без грешки отпадналите модели и тези без публикувана цена
се деактивират, като се запазва избраната публична видимост и се добавя бележка за
причината. Ако се появят отново с цена, се активират само записите, деактивирани
автоматично; ръчно деактивирани записи не се включват. Ограничени и прекъснати
синхронизации не деактивират други продукти. Обработват се само шаблони със запазен
идентификатор `-tempex-ID` в адреса и Tempex източник; ръчно добавени продукти и
складови бройки се изключват. Преди запис се проверява повторно, че продуктът не е
превърнат междувременно в складова бройка или обвързан с покупка/поръчка.

Директните заявки са ограничени до една на 2 секунди. `TEMPEX_REQUEST_INTERVAL_MS` може да
увеличи интервала. При блокиран директен достъп автоматично се използва публичният
HTML четец на Jina с интервал поне 3.3 секунди. Изпращат се само публични каталожни
адреси на Tempex; не се препращат cookies, ключове или други частни данни. Проверява
се, че е заредено същинското продуктово съдържание. `TEMPEX_FETCH_MODE=direct`
изключва този резервен достъп, а `TEMPEX_FETCH_MODE=reader` го избира изрично.

CLI може да запази прочетените публични страници за възстановяване и проверка:
`npm run import:tempex -- --cache-dir=.cache/tempex`. Архивът се използва до 24 часа,
не влиза в Git и не се използва от админ синхронизацията. При повторен старт вече
прочетените страници не се изтеглят отново. Проверка на всички записани полета,
снимки, категории и вътрешни/външни тела срещу този архив:
`npm run audit:tempex -- --cache-dir=.cache/tempex`. Подробният отчет е
`.cache/tempex/audit.json`, включително списък с продуктите без публикувана цена.
Повторното изпълнение обновява записите по доставчик и идентификатор/адрес на продукта.
При Windows с локален сертифициращ орган използвайте `node --use-system-ca --import tsx scripts/sync-tempex-catalog.ts`.
